\chapter{CI/CD Pipeline Explanation}
\label{ch:cicd}

\section{Overview}

The Bitcoin ML Pipeline implements a complete Continuous Integration/Continuous Deployment (CI/CD) strategy using GitHub Actions. This chapter details all workflows, triggers, and automation jobs.

\section{CI/CD Architecture}

The CI/CD pipeline follows a three-branch parallel model triggered by Git events. When code is pushed to the `main` or `develop` branches, three independent pipelines execute simultaneously: the CI pipeline runs code quality checks and unit tests, the ML tests pipeline validates data integrity and feature engineering, and the CD pipeline builds Docker images and trains models. All three branches must pass before allowing a merge to the main branch. This parallel execution reduces total feedback time from ~30 minutes to ~15 minutes.

\section{Workflow Details}

\subsection{1. CI Pipeline (.github/workflows/ci.yml)}

\textbf{Trigger:} Push or Pull Request to `main` or `develop`

\textbf{Job 1: Code Quality} runs Black, isort, Flake8, and Pylint on all Python files to enforce consistent code style and detect issues. Takes ~1-2 minutes and blocks merges if violations are found.

\textbf{Job 2: Unit Tests} executes 50+ pytest tests across Python 3.10 and 3.11 with >70% code coverage. Takes ~2-3 minutes and validates all core logic.

\textbf{Job 3: Data Validation} checks CSV format, row/column counts, missing values, and data types to ensure incoming Bitcoin data is valid. Takes ~30 seconds.

\textbf{Job 4: API Integration Tests} verifies API startup, endpoint availability, and response schema validation. Takes ~2-3 minutes.

\textbf{Total CI Duration:} ~5-10 minutes with parallel execution.

\subsection{2. ML Tests Pipeline (.github/workflows/ml-tests.yml)}

\textbf{Trigger:} Push or Pull Request to `main` or `develop`

\textbf{Purpose:} Validate ML-specific components

\textbf{Job 1: Data Checks} fetches the latest Bitcoin data from CoinGecko API, validates data quality, checks date ranges, and verifies no missing values in critical columns. Takes ~2-3 minutes.

\textbf{Job 2: Feature Engineering Tests} loads raw Bitcoin data, computes all 49 technical indicators, validates feature count, checks for NaN values, and verifies no data leakage occurs. Takes ~2 minutes.

\textbf{Job 3: Model Tests} trains all 11 models (5 classification, 5 regression, Prophet), validates output shapes, and ensures all models can make predictions on test data. Takes ~10-12 minutes.

\textbf{Job 4: Regression Tests} runs the full test suite to verify reproducibility and ensures no regressions in model metrics compared to baseline. Takes ~3 minutes.

\textbf{Total ML Tests Duration:} ~10-15 minutes.

\subsection{3. CD Pipeline (.github/workflows/cd.yml)}

\textbf{Trigger:} Push to `main` branch (after CI passes)

\textbf{Purpose:} Automatically build, train, and deploy

\textbf{Job 1: Build Docker Images} builds API and Dashboard images, then pushes them to Docker Hub or Google Container Registry (GCR). Takes ~5-8 minutes.

\textbf{Job 2: Train Models} fetches the latest Bitcoin data, trains classification and regression models, evaluates them on test data, and versions them in the model registry. Takes ~10-15 minutes and represents the most computationally intensive step.

\textbf{Job 3: Validation} checks that model metrics meet thresholds, compares performance with the previous baseline, and detects any sudden performance degradation. Takes ~2 minutes.

\textbf{Job 4: Deployment} deploys the new images to Google Cloud Run or GKE, updates DNS records, and runs smoke tests to verify the deployment succeeded. Takes ~5 minutes.

\textbf{Total CD Duration:} ~20-30 minutes.

\subsection{4. Scheduled Training (.github/workflows/scheduled-training.yml)}

\textbf{Trigger:} Cron schedule runs daily at 2 AM UTC to retrain models with the most recent Bitcoin data. 

\textbf{Steps:} The workflow fetches the latest 24 hours of Bitcoin data, validates data quality, engineers all 49 technical indicators, trains classification and regression models, evaluates performance on the test set, detects data drift and model drift, versions new models with a timestamp, updates the active model version in the registry, and sends a Discord notification with training results. Takes ~15-20 minutes total.

\subsection{5. Hourly Feature Updates (.github/workflows/hourly-features.yml)}

\textbf{Trigger:} Cron schedule runs every hour at minute 0 to keep technical indicators fresh.

\textbf{Steps:} The workflow fetches the latest Bitcoin data (hourly interval), computes all 49 technical indicators from the rolling window, saves features to CSV format, and uploads the features as a GitHub Actions artifact with 7-day retention policy for potential analysis. Takes ~3-5 minutes per execution.

\section{CI/CD Pipeline Flow}

When code is pushed to the repository, GitHub Actions triggers three independent pipelines in parallel. The CI pipeline (blue branch) runs code formatting, import sorting, linting, and 50+ unit tests. The ML Tests pipeline (green branch) validates Bitcoin data from the API, tests feature engineering with all 49 indicators, trains RandomForest and XGBoost models to verify training works, and runs regression tests to ensure metrics haven't degraded. The CD pipeline (orange branch) builds and pushes Docker images to the container registry and trains new models for deployment. Once all three pipelines complete successfully, the code is automatically merged to the main branch, and the new API and Dashboard images are deployed to production. This parallel execution completes in approximately 20-30 minutes total.

\section{Notifications \& Alerting}

\subsection{Discord Webhooks}

All pipeline events trigger Discord notifications to a configured webhook channel. Success messages announce "Training complete! New model v20251205T052715Z deployed". Failure messages show specific errors like "Training failed: OOM error in model training". Scheduled event messages indicate "Daily training started at 02:00 UTC". Metrics messages display results like "Classification accuracy: 70.0\%, Regression R²: 0.128". This real-time alerting ensures the team immediately knows about successful completions, unexpected failures, or performance issues.

\section{Best Practices Implemented}

\begin{enumerate}
    \item \textbf{Parallel Jobs:} CI, ML Tests, CD run in parallel for speed
    \item \textbf{Fail Fast:} Stop on first failure to save resources
    \item \textbf{Artifact Caching:} Cache pip dependencies and Docker layers
    \item \textbf{Conditional Steps:} Only deploy on main branch
    \item \textbf{Notifications:} Discord alerts for all critical events
    \item \textbf{Version Control:} Git SHA tagged for model traceability
    \item \textbf{Secrets Management:} GitHub Secrets for API keys
    \item \textbf{Documentation:} Each workflow well-commented
\end{enumerate}

\section{Summary}

The CI/CD pipeline enables:
\begin{itemize}
    \item ✅ Automated code quality checks (no manual reviews needed)
    \item ✅ Continuous model retraining (daily with fresh data)
    \item ✅ Safe deployments (all tests must pass)
    \item ✅ Rapid feedback (results in 5-30 minutes)
    \item ✅ Complete traceability (every deployment linked to commit)
\end{itemize}
